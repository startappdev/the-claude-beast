What Is It?

A fully autonomous agent that manages the entire PR lifecycle.

One Command

  • Detect or create PR from current branch
  • Trigger Greptile review via @greptileai

Closed Loop

  • Analyze comments → fix in parallel → push
  • Re-review → repeat until merge or hard stop

Auto‑Merge

  • Squash-merges at score ≥ 4/5 + zero unaddressed
  • Outputs final status report with iteration count
Core Concept One command kicks off a closed loop: PR → review → fix → push → repeat until 4/5.

Safety Guarantees

Hard-coded NEVER rules — built into the agent definition.

No Loops

  • NEVER loops beyond 5 iterations
  • NEVER triggers review while one is in progress

No Bad Merges

  • NEVER merges with score ≤ 3/5
  • NEVER pushes code without validation first

No Duplicates

  • NEVER re-fixes previously handled comments
  • HANDLED_IDS prevents all duplicate work
Design Principle Fail safe, fail fast — every decision point has an explicit exit condition.

The 5‑Step Loop

Cyclic execution with state tracking across iterations.

  • Initialize — Detect or create PR, set all state variables
  • Check­Review — Poll review status; wait if one is in progress
  • Analyze­State — Extract score, filter new unaddressed comments
  • Fix­Issues — Run parallel fixers, validate each file, push
  • Re‑Review — Wait 2 min for auto-trigger or post @greptileai
Exit Condition Steps 2–5 repeat until: score ≥ 4/5 AND unaddressed = 0, OR a hard stop triggers.

State Variables

Four variables maintained across all iterations of the loop.

ITERATION

  • Fix-push cycle counter (hard cap: 5)

HANDLED_IDS

  • Array of comment IDs already fixed — never revisited

LAST_PUSH_ISO

  • Timestamp of last push + 30s buffer for clock skew
Why It Matters State persistence across iterations is what makes the loop safe and non-duplicating.

Parallel Code‑Fixers

One agent per affected file — parallel execution for maximum speed.

Isolation

  • Issues grouped by file; Task tool spawns one agent each
  • Single-file scope prevents cascading changes

Validation

  • tsc --noEmit / py_compile / go build / cargo check
  • Fixes must pass compilation before commit

Speed

  • 5 file issues spawn 5 agents simultaneously
  • Only modified files are staged for commit
Key Property Parallel + isolated + validated — fast fixes that can never corrupt other files.

Hard Stop Conditions

Every decision point has an explicit exit — no unbounded loops.

Success

  • Score ≥ 4/5 + 0 unaddressed → squash-merge

Quality Fail

  • Score ≤ 3/5 after review → stop and report
  • 5 fix-push cycles completed → stop and report

Technical Fail

  • Build validation fails → abort before push
  • No review in 10 min / no X/5 score → abort
Principle The agent never enters an unbounded loop or pushes unvalidated code — period.

Installation

Prerequisites: Claude Code CLI, GitHub CLI, Greptile App + MCP Plugin.

  • Clone & install — git clone github.com/startappdev/agents && ./install.sh
  • Write code on a feature branch, commit and push
  • Run /greptile‑review‑loop — agent creates or finds PR automatically
  • Greptile reviews → agent fixes → loop until 4/5 threshold
  • Read the final status report — score, iterations, files fixed
Required Files greptile-review-loop.md + code-fixer.md in ~/.claude/agents/, slash command in ~/.claude/commands/.
